AVACADO: AI Phone Receptionist

PausedReactTypeScriptFastAPISupabase

A plug-and-play AI employee that answers inbound phone calls for a small business. The owner sets the AI's personality, rules and knowledge in a simple dashboard, with no technical setup. My pitch was a friendlier layer on top of developer-focused voice-AI tools.

What's built

  • A React dashboard with sign-in, agent configuration and phone-number management
  • A FastAPI backend with Supabase (Postgres + auth) and hand-written SQL migrations
  • Agent settings synced to a third-party voice provider (Retell) behind my own provider abstraction, so the provider can be swapped
  • Phone-number provisioning, webhook ingestion and a calls API

Where it stands

No real phone call has gone through it yet. That is the milestone I stopped at, and I treat the MVP as unfinished until one does. The blocker was setting up billing on the voice provider's account, not the code. I also haven't talked to customers or set pricing.

Decisions I made

  • Build on top of an existing voice provider instead of competing with it
  • Keep the provider invisible to customers
  • One user per business for the MVP
  • Build the workflow builder last, after a real call works

What I learned

  • Large parts of what I wanted already existed, so the real question is why a customer would pick mine. I should have asked that before building the dashboard.
  • Stopping before the last step (the first live call) is exactly the 20% habit I'm working on breaking.

Stack

React 19, TypeScript, Vite, Tailwind 4, Python FastAPI, Supabase, Retell. The first repo is github.com/abhiraajr/AVACADO; the code itself is not uploaded yet.
