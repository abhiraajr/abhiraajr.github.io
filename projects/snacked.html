SNACKED: Lunch Snack Pre-Order App

BuiltGoogle Apps ScriptSupabaseJavaScript

A web app where customers reserve snacks before lunch and pay at pickup, while admins manage stock and orders from a dashboard.

How it works

  • One web address routes people automatically: admins land on the dashboard, customers with an order land on the edit-order page, and everyone else sees the storefront
  • Reserving a snack lowers its stock, cancelling puts it back, and marking an order as bought finalizes it
  • Each order is tied to the customer's signed-in Google account, with a limit of one of each snack per order
  • The admin side can restock, delete orders and preview exactly what customers see

Version history

  • v1 to v2: storefront and admin on top of a Google Sheet
  • v3: admin customer-view preview
  • v4: one order per account and editing an existing order
  • v6: moved the data to Supabase with live customer data

What I learned

  • Google's signed-in email can come back empty depending on deploy settings, so admin access has to be tested with the real admin account after every deployment.
  • Two people can take the last item at the same time unless the stock update is wrapped in a lock.
  • Secrets belong in script properties, never in the code file.

Stack

Google Apps Script (server and HTML pages) with Supabase for the database. The first repo is github.com/abhiraajr/SNACKED; the code itself is not uploaded yet.
